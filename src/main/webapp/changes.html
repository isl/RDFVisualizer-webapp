Changes

2026-08-12: dev branch changes include:
  • The requirement to have at least an rdf:type specified has been removed. Now all uris included in the .ttl or trig file are listed in the table of file contents.
  • Applied the following clustering logic:
    • We first sort uris based on the maximum sum of inbound and outbound links to other uris (excluding outbound rdf:type and literal values)
    • The first uri in this list with the maximum number of links defines the first cluster.
    • During cluster's identification we keep a list of neighbor uri links for all identified clusters. All neighbor uris of all identified clusters are excluded by the list of cluster candidates.
    • Next clusters are defined by the first uri that is not included in the visited neighbor links of identified clusters
    • Uris that have been used as classes (i.e. as ranges of an rdf:type statement) are also excluded from the list of potential cluster candidates
  • Table of file contents additions:
    • line background color notation for all uris that are defined as clusters
    • Each label is followed by the list of specified classes in brackets e.g. Acropolis of Athens 8712059 [ E53_Place ]
    • Uris that have been used as clases (i.e. as ranges of an rdf:type statement) are suffixed by a (class) notation
    • Visualize button opens a new window in order to avoid losing context of the file contents.
2026-08-11: dev branch. started support of the following features:
  • Added new columns in the subjects table for graph uri (useful for trig files) and direct links count in each graph (to assist finding the best starting point).
  • Supported listing of multiple uris with the same configured label property (e.g. rdfs:label) in the contents table of each file. Before this change each label was associated with just one uri - not all uris where listed.
  • Supported listing of uris without the configured label property (e.g. rdfs:label) in the contents table of each file. The only obligatory field for uris displayed in the table is to have at least one class specified (rdf:type property) in its container graph.
       * Note: The visualize function does not yet work with uris without the configured label property.
  • Started support of trig files. The selection table includes uris from all graphs including the default one if specified.
       * Note: Trig files are not yet fully supported - they require named graph related adaptations.
2026-08-11: Addition of Docker deployment support files and instructions. This first Docker version is tagged as 2.1 and corresponds to the code with timestamp: 2023-09-08T17:40 after applying the following minimal adaptation changes:
  • Default home page set to configuration in case no resource has been selected in the url parameters
  • Default page length has been set to 100
  • Default value for show incoming links has been set to true
  • Addition of debug parameter in config.properties. When enabled it logs messages produced by exception catch statements (such as .ttl parsing errors).
  • Moved properties files in a config subfolder in order to facilitate volume mapping of docker containers
  • Adapted footer messages to be synchronized with commit status
